# Security checklist

The Firebase web config (apiKey, projectId…) is **public by design**: every visitor of the site downloads it.
It identifies the project; it does not grant access. What protects the data is:

1. **Firestore rules** (`firestore.rules`): who can read and write each collection.
2. **API key restrictions** in Google Cloud: which websites and APIs may use the key.
3. **Authentication settings**: which domains may sign in, and how accounts are created.

## 1. Publish the Firestore rules (do this first)

1. In `firestore.rules`, replace `owner@example.com` in `isOwner()` with the real owner email(s).
2. Firebase console → Firestore Database → **Rules** → paste the whole file → **Publish**.
   Or, with the Firebase CLI: `firebase deploy --only firestore:rules`.

What changed (v73):

- `isOwner()` now requires a **verified** email. The online shop lets anyone create an account,
  so without this an attacker could sign up with the owner email and make themselves admin.
- `orderTrack` (public order tracking) only accepts the fields the shop really writes.
- `problemList` (new): staff read, front desk can add problems from the ticket window.
- Public ticket tracking records no longer store the customer's phone number.

## 2. Restrict the API key

Google Cloud console → APIs & Services → **Credentials** → the "Browser key (auto created by Firebase)":

- **Application restrictions → Websites**:
  - `https://chihabfortas.github.io/*`
  - `http://localhost:8765/*` (local testing)
  - any custom domain you use
  - the Android app uses the live site, so it is covered by the GitHub Pages entry.
- **API restrictions → Restrict key** to: Identity Toolkit API, Token Service API, Cloud Firestore API,
  Firebase Installations API (and Firebase Cloud Messaging API if you use notifications).

## 3. Authentication

Firebase console → Authentication → Settings:

- **Authorized domains**: keep only `chihabfortas.github.io`, `localhost` and your own domains.
- **User account management → Email enumeration protection**: on.
- **Password policy**: require at least 8 characters.

## 4. Good habits

- Never put service-account JSON files, admin SDK keys or passwords in the repository.
  The repository already ignores `mobile/android` and `mobile/ios`.
- Keep `js/firebase-config.js` generated by the build (from GitHub Secrets); do not commit live values.
- Review the **Users** page regularly and switch off accounts of people who left.
- Optional, stronger: turn on **Firebase App Check** (reCAPTCHA v3) so only your site can use the project.
